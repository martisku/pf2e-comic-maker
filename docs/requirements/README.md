# Feature Requirements

Feature requirements define what the product should do.

Store one requirement per file where practical.

Example:

```text
docs/requirements/chapter-management.md
```

## Suggested structure

```markdown
# Feature name

## Problem

What problem are we solving?

## Goal

What should the user be able to accomplish?

## User workflow

How should the feature work from the user's perspective?

## Requirements

- Requirement
- Requirement

## Acceptance criteria

- Observable result
- Observable result

## Out of scope

What are we deliberately not solving?

## Open questions

Decisions that still need to be made.
```

Requirements should focus on product behavior rather than technical implementation.
