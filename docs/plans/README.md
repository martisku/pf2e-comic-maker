# Implementation Plans

Implementation plans describe how a requirement should be implemented in the current system.

Plans should be created only after inspecting the relevant requirement and existing codebase.

## Suggested structure

```markdown
# Implementation plan: Feature name

Status: Draft

## Requirement

Reference the requirement being implemented.

## Current state

Relevant existing behavior and architecture.

## Proposed solution

High-level technical approach.

## Data model

Required persistence or domain model changes.

## Backend

Relevant backend changes.

## Frontend

Relevant browser/UI changes.

## File changes

Expected important files to create or modify.

## Testing

How the implementation will be verified.

## Risks and tradeoffs

Known concerns and important design choices.

## Alternatives considered

Other reasonable approaches.

## Implementation steps

1. Step
2. Step
3. Step

## Open questions

Anything that must be resolved before approval.
```

## Status

Use:

```text
Draft
Under Review
Approved
Implemented
```

A plan should not normally be implemented before it is approved.
